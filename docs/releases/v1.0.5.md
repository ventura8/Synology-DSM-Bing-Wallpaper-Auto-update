# v1.0.5 - SonarQube Cloud Analysis and Hash-Pinned Dependencies

## Summary
Adds SonarQube Cloud static analysis as a blocking CI gate and clears every
finding from its first analysis of `main` (87 issues). The product script
changes are hygiene rather than behavior: error diagnostics now go to stderr,
every function ends with an explicit `return`, and conditional tests use `[[`.
Dependencies are now pinned down to the transitive tree with hashes, all
GitHub Actions are pinned to commit SHAs, and a long-standing hang in the
local test orchestrator is fixed so `run_tests_local.ps1` completes.

## Why This Change
- The repository had no static analysis beyond ShellCheck and Ruff. Sonar
  covers Bash, Python, PowerShell, Dockerfile, and workflow YAML, and its
  first scan surfaced 87 issues — including error output going to stdout,
  where a caller cannot separate it from normal logging.
- Action pins were tags, which are mutable: a moved tag silently changes what
  CI executes. Python dependencies pinned only direct versions, leaving the
  transitive tree free to change between runs.
- `./scripts/testing/run_tests_local.ps1` never completed on a Linux host, so
  the documented local pipeline could not actually be run end to end.

## What Changed

### 1. Product script (`bing_wallpaper_auto_update.sh`)
- All eleven `Error:` diagnostics now write to stderr (`>&2`). Callers that
  capture stdout — DSM Task Scheduler output, a wrapper script — previously
  received failure text mixed into normal logging. Exit codes and messages
  are unchanged.
- Every function that fell off its end now closes with an explicit
  `return 0`, so a function's exit status is stated rather than inherited
  from whatever command happened to run last.
- All conditional tests use `[[ ... ]]` instead of `[ ... ]`. Every
  right-hand side was already quoted, so the comparisons are unchanged; the
  scripts have always declared `#!/bin/bash`.
- `sanitize_conf_value` assigns its positional parameter to a local `raw`
  before use. Header version bumped to 1.0.5.

### 2. SonarQube Cloud integration
- `sonar-project.properties` is the single source of truth for scanner
  settings, shared unchanged by local runs and CI. `tests/**` is listed in
  `sonar.exclusions` so the tree is indexed as test code only — with
  `sonar.sources=.` it would otherwise be indexed twice and abort the scan.
- `scripts/quality/sonar_scan.sh` runs a pinned `sonar-scanner-cli`
  container, so a local scan needs no scanner installation.
- New `sonarqube` CI job scans and then blocks on
  `sonarqube-quality-gate-action`, failing the pipeline on a red gate. It is
  gated on the `SONAR_ENABLED` repository variable and needs a `SONAR_TOKEN`
  secret. Automatic Analysis and CI-based analysis are mutually exclusive;
  enabling this job requires turning Automatic Analysis off.
- `tests/cobertura_to_sonar.py` restates the merged kcov report in Sonar's
  generic coverage format, since Sonar cannot read Cobertura for shell code.
  `coverage-report` publishes the merged `cobertura.xml` and `sonarqube`
  runs after it to consume that artifact.

### 3. Supply-chain pinning
- All eleven GitHub Actions across `ci.yml` and `release.yml` are pinned to a
  full 40-character commit SHA with the version in a trailing comment. A tag
  can be moved; a SHA cannot.
- New `requirements/dev.lock`, generated from `requirements/dev.txt` with
  `pip-compile --generate-hashes`, pins 19 packages including the full
  transitive tree. CI installs from it with `--require-hashes
  --only-binary :all:`, so a wheel that does not match its recorded hash
  fails the build and no sdist can execute `setup.py` at install time.
  `dev.txt` remains the hand-edited input and carries the regeneration
  command; the two must be committed together.
- Test-container `chmod 777` on CI coverage mounts reduced to `755` — the
  containers run as root and never needed the wider mode.

### 4. Local test orchestrator (`scripts/testing/run_tests_local.ps1`)
- Fixed a hang that prevented the script from ever completing. `Start-Job`
  buffers a job's output until `Receive-Job`, which only runs after
  `Wait-Job` returns, so a lane that out-talks that buffer blocked `docker`
  on write; that stopped the traced script, and kcov then busy-waited at
  100% CPU on a child that could never progress. Each lane now writes
  straight to `reports/agent-logs/<lane>.log`, replayed once the jobs finish.
- kcov writes as root, so the previous run's `coverage/` is now removed from
  inside a container (the invoking user cannot delete it), and the merged
  report's ownership is reclaimed only when it is actually owned by another
  uid — under rootless Docker the container's root is already the invoking
  user, and chowning there would resolve to a subordinate uid.

### 5. Dependency refresh
- `ruff` 0.16.7 → 0.16.8 (`requirements/dev.txt` and the `ruff-pre-commit`
  hook, kept in lockstep); `docker/setup-buildx-action` v4.3.0 → v4.4.1;
  `docker/build-push-action` v7.3.0 → v7.4.0.
- Verified already current: pip, pre-commit, mypy, yamllint,
  `pre-commit-hooks`, `pre-commit-shfmt`, `shellcheck-py`, `mirrors-mypy`,
  all `actions/*` pins, `CodeCoverageSummary`,
  `sticky-pull-request-comment`, `action-gh-release`, PSScriptAnalyzer
  1.25.0, kcov v43, `ubuntu:24.04` as the DSM-mock base.
- `tests/Dockerfile.dsm_mock` installs with `--no-install-recommends`, sorted
  package names, and a single merged `RUN` layer.

## Validation
- `./scripts/quality/quality_check.sh` passed clean (no suppressions added).
- All three DSM-mock lanes (unit, component, e2e) passed via
  `./scripts/testing/run_tests_local.ps1` — four consecutive complete runs,
  the first time the orchestrator has finished on a Linux host.
- SonarQube Cloud quality gate passed: 0 new issues, 0 accepted issues,
  0 security hotspots, security/reliability/maintainability all rated A.

## Coverage
- Line coverage: **96.0%** (144/150), threshold **90%**, up from 95.80%. The
  explicit `return 0` statements are executable lines and are all covered, so
  both the numerator and denominator grew. `assets/coverage.svg` regenerated
  from this run.

## Policy Guarantees Added
- GitHub Actions are pinned to commit SHAs, not tags.
- Python tooling installs only from a hash-pinned lock, wheels only.
- Sonar findings fall under the existing no-suppressions rule: fix the issue
  rather than resolving it as "Won't Fix" or adding `NOSONAR`.

## Notes
- Two Sonar security hotspots are reviewed as safe rather than changed,
  because both are required by the tests they support: the DSM mock image
  must run as root to simulate DSM, and `tests/archive_write_cases.sh` must
  `chmod 777` a fixture mount to prove that a world-writable mount is
  refused. Both are recorded in `AGENTS.md` as standing exceptions.
- SonarQube Cloud's free plan analyses `main` and pull requests only, not
  feature branches, so a local scan of a feature branch will be rejected.
