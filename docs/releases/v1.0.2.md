# v1.0.2 - Download TLS Hardening and Archive Path Safety

## Summary
This release hardens the wallpaper script against local network MITM abuse and
archive path traversal by requiring TLS certificate verification, validating
JPEG content before system writes, sanitizing login metadata for
`synoinfo.conf`, and constraining archive filenames to a validated Bing date.

## Why This Change
- Close HIGH-severity risk from `wget --no-check-certificate` when the script
  runs as root on a NAS.
- Close MEDIUM-severity archive path traversal via unsanitized API `enddate`.
- Align product safety with existing development standards (sanitize conf
  values; fail closed on bad downloads).

## What Changed

### 1. TLS Verification Restored
- Removed `--no-check-certificate` from both Bing API and image `wget` calls in
  `bing_wallpaper_auto_update.sh`.
- Fail closed if certificate verification fails; do not disable TLS as a
  workaround.

### 2. JPEG Validation Before System Writes
- Added `validate_downloaded_jpeg` to require JPEG SOI magic bytes (`FF D8 FF`)
  after download and before any `cp` / `synoinfo.conf` updates.

### 3. Archive Date Sanitization and Path Containment
- Added `validate_archive_date`: archive `SAFE_DATE` must be exactly eight
  digits and unchanged by digit-only filtering (Bing `YYYYMMDD`).
- Archive filenames use `SAFE_DATE` (not raw `DATE`).
- Added `ensure_archive_within_save_path` (`realpath` when available) so
  archives cannot escape `SAVE_PATH`.

### 4. synoinfo.conf Value Sanitization
- Added `sanitize_conf_value` to strip `"`, `` ` ``, `\`, `$`, and newlines from
  title/copyright before writing `login_welcome_title` /
  `login_welcome_msg`.

### 5. Tests and Mock Updates
- Updated `tests/mocks/wget` comments and added failure modes:
  `non_jpeg_download`, `traversal_date`.
- Extended `tests/run_kcov_cases.sh` expected-failure coverage for those modes.
- Coverage remains above the mandatory **90%** floor (validated locally at
  **95.3%**); `assets/coverage.svg` updated.

### 6. Documentation and Agent Guidance
- Updated `docs/development_standards.md` system-safety rules (TLS, JPEG,
  archive date validation).
- Updated `AGENTS.md`, `README.md`, and `docs/project_overview.md` to match
  product invariants.
- Added this release document: `docs/releases/v1.0.2.md`.

## Policy Guarantees Added by This Release
- TLS certificate verification stays enabled on product downloads.
- Non-JPEG payloads never reach DSM system wallpaper paths.
- Archive mode rejects non-`YYYYMMDD` dates and keeps files under `SAVE_PATH`.
- Login metadata written to `synoinfo.conf` is sanitized against quote/shell
  metacharacters.

## Notes
- If a NAS lacks a current CA bundle, install/update CA certificates rather than
  reintroducing `--no-check-certificate`.
