# v1.0.7 - PowerShell test coverage in Sonar

## Summary

After v1.0.6, SonarQube Cloud began counting the three PowerShell scripts on `main` (147 lines,
all uncovered), so overall coverage fell to **68.1%** and the Sonar quality gate failed. This
release adds a Pester suite for them and feeds its coverage to Sonar. It also includes the
line-length gate fix merged after v1.0.6.

## What Changed

### Pester suite

- `tests/pester/*.Tests.ps1` cover `lint_powershell.ps1`, `quality_check.ps1` and
  `run_tests_local.ps1`: happy paths plus every failure branch.
- Only process boundaries are faked: `docker`, `python` and `stat` are PATH stubs in
  `tests/pester/stubs/` (executables, because `run_tests_local.ps1` starts its lanes with
  `Start-Job` in a separate process). PSScriptAnalyzer / PSGallery cmdlets are Pester mocks.
- `tests/run_pester.ps1` runs the suite under Pester 6.2.0 code coverage, enforces a **90%**
  line floor, and writes `coverage-powershell.xml` in Sonar's generic format.

### CI and Sonar

- New `powershell-tests` job; `sonarqube` now also needs it and imports the report through
  `sonar.coverageReportPaths`.

### Line-length gate (PR #7)

- `scripts/quality/check_line_length.py` scanned only `scripts/`; it now scans the whole repo
  minus generated trees.

## Validation

- `./scripts/quality/quality_check.sh` — pass.
- Pester — 21 tests pass; Python — 22 tests pass.

## Coverage

- PowerShell scripts: **91%** of lines (floor 90%).
- Python helpers: **97%**; shell script (kcov): **96%**.
- Expected Sonar overall: ~**95%** (was 68.1% on `main`).
