# v1.0.6 - Python helper tests and Sonar coverage

## Summary

SonarQube Cloud reported **42.1%** coverage although the product script sits at **96%** under kcov:
the Python helpers under `scripts/` were analysed as source with no coverage report at all. This
release tests them, enforces a 90% floor on them, and feeds the report to Sonar.

## Why This Change

Sonar counts every analysed source line. Five helpers (198 lines) had **0%**, outweighing the
well-tested shell script. The one existing Python test (`tests/test_check_coverage_threshold.py`)
was never run by CI.

## What Changed

### Python test lane

- New tests: `tests/test_check_complexity.py`, `tests/test_check_line_length.py`,
  `tests/test_lint_wrappers.py`; shared `tests/_loader.py` loads scripts by path so the real
  implementation runs. Only `subprocess.run` / `shutil.which` (process and PATH boundaries) are mocked.
- `pyproject.toml`: `[tool.coverage.*]` — source `scripts`, relative paths, `fail_under = 90`.
- `requirements/dev.txt` + `dev.lock`: `coverage==7.16.2` (hash-pinned).

### CI

- New `python-tests` job (parallel with the kcov lanes) runs the suite under coverage.py and
  uploads `coverage-python.xml`.
- `sonarqube` now also needs `python-tests` and imports the report through
  `sonar.python.coverage.reportPaths` in `sonar-project.properties`.

## Validation

- `./scripts/quality/quality_check.sh` — pass.
- Python lane — 21 tests pass.

## Coverage

- Python helpers: **97%** (floor 90%).
- Product shell script (kcov): unchanged, **96%**.
- Expected Sonar overall: ~**97%** (was 42.1%).
