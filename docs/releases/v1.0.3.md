# v1.0.3 - Agent Workspace Overhaul and Dependency Refresh

## Summary
This release does not change wallpaper/apply logic in
`bing_wallpaper_auto_update.sh`. It expands the agent tooling (a dedicated
`release` skill, tool adapters for Claude Code and Gemini, an automated
GitHub Release workflow) and refreshes every pinned dependency — Python
quality tools, pre-commit hook revisions, GitHub Actions, and the
PSScriptAnalyzer module — to their current stable versions.

## Why This Change
- Close the gap between this repo's agent workspace and the broader pattern
  it follows (`AGENTS.md` as source of truth, `.agents/skills/` playbooks,
  thin tool-specific adapters) by adding the pieces that were missing:
  `CLAUDE.md`, `GEMINI.md`, and a `release` skill distinct from the existing
  doc-drift-only `release-hygiene` skill.
- Automate GitHub Release publishing so it can no longer drift from
  `docs/releases/*.md`, and keep pinned tooling current so CI doesn't quietly
  fall behind on security and bug fixes in the lint/test toolchain.

## What Changed

### 1. Agent Workspace
- Added [`CLAUDE.md`](../../CLAUDE.md) and [`GEMINI.md`](../../GEMINI.md) as
  thin adapters pointing at `AGENTS.md` (Claude Code auto-loads `CLAUDE.md`;
  this repo previously had no such file).
- Added [`.agents/skills/release/`](../../.agents/skills/release/): create
  `feature/vX.Y.Z`, write `docs/releases/vX.Y.Z.md`, then request explicit user
  confirmation before pushing the branch and opening the PR. After the PR merges
  into `main`, request confirmation again before tagging the merge commit and
  pushing the tag.
- Updated `AGENTS.md`, `docs/ai_instructions.md`, `.instructions.md`,
  `.prompt.md`, and `.agents/skills/release-hygiene/SKILL.md` to reference the
  new adapters and skill.

### 2. Automated Release Publishing
- Added [`.github/workflows/release.yml`](../../.github/workflows/release.yml):
  triggers on any `v*` tag push, validates the tag is on `main`, waits for a
  green CI Pipeline on that commit (polls if still running), fails closed if
  `docs/releases/<tag>.md` is missing, otherwise publishes the GitHub Release
  using that file as the body and attaches `bing_wallpaper_auto_update.sh` + a
  generated `SHA256SUMS`.
- `.agents/skills/ci-maintainer/SKILL.md` and `AGENTS.md`'s CI Parity section
  now cover both workflows.

### 3. Dependency Refresh (all pinned tooling)
- **Python** (`requirements/dev.txt`): pip 26.1.2 → 26.2.1, pre-commit 4.0.1 →
  4.6.2, ruff 0.6.9 → 0.16.4, **mypy 1.11.2 → 2.3.1** (major version — no new
  type errors), yamllint 1.35.1 → 1.38.0.
- **Pre-commit hook revisions** (`.pre-commit-config.yaml`, kept in lockstep
  with the versions above): `pre-commit-hooks` v5.0.0 → v6.0.0,
  `pre-commit-shfmt` v3.11.0-1 → v3.13.1-1, `shellcheck-py` v0.10.0.1 →
  v0.11.0.1-1, `ruff-pre-commit` v0.6.9 → v0.16.4, `mirrors-mypy` v1.11.2 →
  v2.3.1, `yamllint` mirror v1.35.1 → v1.38.0.
- **GitHub Actions** (`.github/workflows/ci.yml`): `actions/checkout` v7.0.0 →
  v7.0.1, `actions/setup-python` v6.3.0 → v7.0.0, `docker/setup-buildx-action`
  v4.2.0 → v4.3.0. All other pins were already current.
- **PowerShell**: `PSScriptAnalyzer` module pin in
  `scripts/lint/lint_powershell.ps1` 1.24.0 → 1.25.0.
- `ruff-format` 0.16.4 reformatted two files
  (`tests/test_check_coverage_threshold.py`, `tests/transform_coverage.py`) —
  spacing-only, no behavior change.
- Left the `ubuntu:24.04` base image and `kcov v43` pin in
  `tests/Dockerfile.dsm_mock` unchanged: the Ubuntu version is an intentional
  DSM-mock environment pin, not stale tooling, and `v43` is kcov's latest
  release.
